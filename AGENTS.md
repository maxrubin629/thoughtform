# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable design decisions

- The map uses solid circular lobes connected by thick, smoothly fused organic necks. Never substitute rectangular cards, generic bubbles, or thin connector lines.
- Large starting ideas sit left-ish and children progress primarily to the right; crowded branches can wrap above, below, and sideways.
- Controls should communicate through familiar icons instead of word buttons wherever possible.
- Voice capture uses a circular microphone state with a timer or pulse. Do not introduce a scrolling waveform.
- The two selected visual targets are `designs/organic-paper-studio.png` and `designs/nocturne-focus-canvas.png`.
- Voice capture creates a node only after a complete spoken thought; do not continuously rewrite the graph from partial speech.
- The silent GPT-6 Luna controller may autonomously commit constructive map changes from completed thoughts; uncertain or destructive interpretations and novel AI ideas remain proposal-only. Foreground Partner changes the map only for explicit user commands.
- Cluster and hierarchy modes are switchable views of one underlying graph, not separate documents.
- AI presence can switch between quiet and proactive without leaving the canvas. Provenance stays hidden by default but can be revealed.
- The solo-first result is a clear thinking map plus a written synthesis, stored as a local-first artifact; it is not an action-plan generator.
- Nodes remain distinct and draggable while their fused necks visually stretch and pull with them.
- Dragging a bubble body moves it; dragging a small exterior handle previews and creates a connection. The handle appears on hover or selection and has a separate generous hit target outside the body. Lock the gesture at pointer-down; proximity while moving never creates a connection. Dropping on empty space, Escape, pointer cancellation, or a second touch cancels the connection. Reject self-connections, duplicate links, and pending proposal targets. Keep occasional bubble actions in a right-click/long-press menu with an accessible More actions entry; clicking or keyboard-activating the handle opens a target chooser.
- Create and connect are distinct actions: plus icons create new thoughts; the exterior connection handle uses a neutral link icon with “Connect existing” guidance. Preserve drag-to-connect and body-drag-to-move. Keep the warm-white floating chrome, without a coral stalk or a plus used for connecting existing bubbles.
- The top dock exposes New thought; the selected-thought strip exposes New connected thought and More actions. Pin, keep aside, sources, and Partner exploration live in the contextual menu. Double-click creation immediately opens the thought editor; a connected-thought editor names its parent. Enter saves, Shift+Enter adds a line, and Escape closes. Explicit manual creations produce distinct bubbles even when their labels match; transcript mapping still deduplicates repeated ideas.
- Canvas navigation uses two-finger trackpad scrolling and two-touch centroid panning. Pinch gestures zoom; one-pointer dragging on empty canvas remains available.
- Map motion follows `sites/fluid-bubble-lab`: Jelly defaults, creation-time rest lengths, a 0.8-1.2x neutral spring band, lobe and web clearance, damped release inertia, and soft edge collisions.
- Ghost-proposal tethers must be constructed from explicit exterior boundary anchors on both rendered shapes, with control handles that keep the path outside both interiors. Render the tether beneath solid material, use round dots with anchored endpoints, and never target either shape's center.
- Proposal ghost lobes must open clear of committed lobes and other proposal lobes, and they participate in the same browser-local cluster physics as committed lobes: dragging, release inertia, soft collisions, tether springs, and wobble/deformation. This transient motion moves the tether visually but never changes canonical proposal operations, source revision, or persisted map geometry.
- The workspace rail is a 60 px shared layout token; floating-panel offsets must derive from the same token at every breakpoint.
- Sidebar chrome matches the top dock’s warm white and floats above the canvas with inset edges and a soft shadow. Buttons are circular; selected states use white surfaces and gentle elevation rather than hard outlines or an edge marker. Keep neutral icons and avoid orange or peach button fills.
- The active favorites star is the sidebar’s color exception: use a soft yellow fill and a muted gold stroke. An inactive star stays neutral.
- Bubble size primarily communicates idea importance. Treat text length as a readability constraint, not an importance signal. Preserve complete captured and typed text; importance scoring and overflow presentation remain undecided.
- Graph focus traversal must be cycle-safe. Pending ghost proposals cannot receive committed connections until they are accepted.
- Hierarchy mode uses the live graph, distributes proposal siblings outside their parent, reserves the fixed top and voice-control chrome, and does not run cluster spring physics.
- Manual and voice thoughts preserve the user's proposal-layer visibility choice; only creating a new AI proposal may reveal that layer.
- Nocturne uses its own floating tool rail, dark panel surfaces, lower-left companion prompt, and luminous root treatment rather than inheriting Paper chrome.
- Newly committed stems use a 350 ms two-phase growth: the head reaches the target exterior at 70%, then widens continuously into the final target flare through the remaining 30%. Reduced-motion mode may reveal the completed connection immediately.
- The canvas keeps its grab cursor over lobes, empty space, and fused stems. Clicking a committed stem pops and removes that connection with the lab's 520 ms burst; dragging from the same stem pans instead.
- Connection-pop motion has one causal clock and a visible origin: the rupture begins at the exact click point, travels toward both endpoints, and each endpoint lobe plus its surviving stems deform only when that wave reaches them. Never start both endpoint wobbles generically at click time.
- Armed connection growth has one causal clock: the source lobe ripples directionally at launch, the target compresses in the direction of travel when the head contacts its exterior, and a smaller reverse impulse returns to the source 72 ms later. Attached stems inherit each lobe's deformation, and the contact flare must grow continuously rather than snap on.
- The workspace preserves the established canvas interaction and physics behavior. Connection growth uses whole-lobe directional launch, contact, and return wobble on one causal clock; connection pops use click-origin rupture. Pending visual edges remain presentation-only.
- Double-clicking genuinely empty canvas space creates and selects an unconnected freeform `New thought` lobe at that world position. Double-clicks on lobes, proposals, committed stems, or controls must never spawn another lobe.
- Rectangle selection is an explicit canvas mode: Paper exposes it in the top dock and Nocturne in its floating rail. The drag box intersects lobes in world coordinates, selected lobes keep their organic form with a solid exterior selection contour, and Escape exits the mode and clears the set.
- Rectangle selection owns one-pointer canvas gestures while active, so it never drags lobes, pans, pops stems, edits, or creates freeform thoughts. Bulk deletion preserves the root, removes every edge attached to deleted lobes, and records the whole removal as one undo step.
- Cluster physics advances from one authoritative simulation state. React may render a mirrored snapshot, but a committed render must never write older node positions back into the live simulation; adding or moving a lobe must settle forward without frame-alternating global shake.
- Paper committed material follows a restrained 2.5D treatment grounded in `designs/organic-paper-studio.png`: every committed Paper lobe and stem uses the same original coral `#f78269`, never varied or desaturated by depth, horizontal position, or lobe size. At rest, keep that fill flat and continuous across lobe-stem junctions with only a soft down-right undershadow for paper separation. During actual deformation or movement, a very low-contrast local cue may briefly darken the compressed/trailing side and warm the stretched/leading edge; it must decay completely with the physical motion and disappear under reduced motion. Never add glossy rims, permanent internal highlights, specular sheen, or ambient material animation. Preserve the current physical geometry and causal interaction motion; Nocturne keeps its existing material.
- There is one conversation-first workspace at `/`. Classic mode is retired; old `?mode=classic` and `?mode=session` links open the workspace and remove the obsolete mode parameter. The server-owned local JSON session is canonical for transcript, semantic graph, revisions, proposals, and reversible map history, while the browser owns transient physics, deformation, and animation. The transcript is complete and append-only, partial speech appears only in the voice caption, and the map changes only after a complete utterance commits. Each utterance condenses into at most three concise bubbles with exact source spans; provenance highlights only the selected bubble's spans. Workspace lobes retain stable radius and typography behavior: connectivity and conversational heat never resize a committed lobe or its text. Repeated ideas revisit the existing bubble instead of duplicating it. Direct edits are reversible; movement, connections, deletion, proposal acceptance, undo, and redo appear in map history and the actor-labelled activity record without changing the transcript. GPT-Live handles foreground conversation and delegates deeper reasoning and explicit map requests to gpt-6-luna at high effort; a separate silent GPT-6 Luna controller maps complete thoughts. Uncertain or destructive controller interpretations remain reviewable proposals. Curator work remains proposal-only, uses ghost tethers and evidence-bearing review cards pinned to a source map revision, and those cards reuse the normal Paper proposal badge, surface, and accept/dismiss action language. Session mode keeps Maps, conversation and activity controls alongside the normal Paper rail anatomy and full Paper top dock. Curator proposals rebase at acceptance, drop invalid or duplicate operations, report fully stale proposals, and stagger multi-link acceptance by about 160 ms.
- In the Conversation panel, consecutive finalized utterances from the same speaker render as one conversational turn while their canonical utterance IDs and exact provenance spans remain separate. Partner-side map operations appear inside that turn as silent generic visual statuses such as “Created a bubble” or “Removed a connection”; never speak those statuses or expose node text, IDs, or other operation specifics there.
- Partner is a foreground GPT-Live conversation partner, not an autonomous map steward. Spoken replies stay warm, attentive, inquisitive, and brief—normally one or two short sentences with at most one question—and GPT-6 Luna executes delegated map tools only for explicit spoken commands. Map work stays silent: no tool preambles, no “captured” or “done” confirmations, and no questions asking what should be added to the map. The server-side gpt-6-luna controller at high effort independently organizes completed transcript deltas without delaying speech; it may commit confident changes or create reviewable proposals for uncertain or destructive interpretations. GPT-Live uses client delegation; the app preserves original speaker fragments and validates semantic completeness before creating canonical utterances. Transcript gaps and audio silence alone never establish a complete thought. Clear UI and explicit Realtime map commands rebase once against the newest canonical revision when the map controller commits concurrently; stable identifiers and reducer validation still reject invalid targets. A bubble may carry several exact source spans from separate finalized speech fragments. If the wrong thought becomes root, the controller uses one atomic, reversible central-idea reassignment that preserves the previous root as its own bubble and keeps existing relationships; never relabel one semantic idea into another merely to change the root.
- In the session UI, both realtime-partner and internal-curator actions are presented under the single user-facing identity `Partner`. Never expose the curator role name or give it a distinct visual identity; the internal actor distinction may remain for orchestration and history data.
- Use `Partner` only as a speaker or actor label (conversation turns, live captions, activity). Elsewhere prefer functional copy: the settings heading reads `Suggestions`, suggestion cards read `Suggestion`, the chat box reads `Message` / `Type a thought…`, and setup errors describe the missing OpenAI key rather than the persona.
- The creative curator is a downstream, proposal-only loop, never a peer of the transcript map controller. It may evaluate only after the primary GPT-6 Luna map-controller pass has fully settled, and it must defer again if another controller pass is scheduled or active. Wait 10 seconds after that completion, inspect only the eight most recent utterances plus the canonical map, and surface at most one coherent card of three operations. Require three new user turns between curator evaluations, allow only one pending proposal, and cap curator proposals at three per session. Zero output is normal; suggestions must add a missing implication, tension, assumption, alternative, or non-obvious connection rather than paraphrase the conversation.
- Hovered lobes emit a soft light glow with a continuous fade into the canvas. Keep the wider falloff, about 24 screen pixels, at restrained opacity; reduce intensity rather than shrinking its spread. Never draw a stroked ring or a hard outer edge for hover. Selected lobes use a solid exterior contour rather than a glow, dotted line, or dashed line.

## Thinking workspace behavior

- The session title and local save state stay visible. A single resizable detail drawer holds conversation, sources, suggestions, and synthesis. Selection establishes explicit context for voice and text; discussing a proposal leaves acceptance unchanged.
- Keep persistent status and voice-control copy concise: successful saves read `Saved` without a dot, and the idle microphone caption reads `Start talking`.
- Button labels name their action in a few plain words. The suggestion shortcut reads `Review suggestions`; avoid vague teaser copy such as `A new angle to consider`.
- Prefer brief, functional UI copy and remove redundant instructions. The example canvas needs no introductory sentence above its conversation button. Account initials use 14 px type within the existing circular rail button.
- Quiet mode suppresses unsolicited creative jobs; hiding proposals only affects visibility. Paused mapping preserves the transcript and its unprocessed cursor, blocks late map writes, and resumes the backlog when enabled.
- Each complete controller interpretation is one atomic undo step. Pinned lobes keep their location through physics and automatic changes; kept-aside ideas remain visible and available for discussion without automatic rewriting or restructuring.
- Preserve the current camera during background updates. Restore per-map view state and offer a return to the previous view after deliberate navigation. Recent-change notices are temporary and do not change committed material or selection appearance.
- Voice start, mute, and end are distinct actions. User and Partner captions can overlap; backend progress and errors are separate from audio state. Keep the connection alive through session.closed before normal cleanup.
- Synthesis is persisted with its source map revision and becomes visibly outdated after map changes. Export includes the map, synthesis, and source record. Schema migrations preserve a backup of earlier session files.

- Lasso is an explicit selection mode alongside rectangle selection. Its closed freehand path intersects lobes in world coordinates, reuses the solid selection contours and root-safe bulk undo, and owns one-pointer gestures while active. Escape exits and clears selection; pointer cancellation or a second touch cancels the unfinished selection.

- Rectangle and lasso selection share one top-dock control with a mode picker, rather than separate toolbar buttons. The trigger shows the chosen mode; Escape exits selection.
- The drawn rectangle and lasso selection regions have dotted outlines. This applies to the drag overlays, not their toolbar icons or the solid contours around selected lobes.

- Use “Suggestions” throughout the interface, including activity and undo labels. Internal protocol names may remain unchanged.
- Keep canvas copy minimal. Conversation belongs in the rail and Suggestions in the dock and ghost badge; omit duplicate bottom prompts.
- The compact map size is the new 100% baseline: use 0.675 CSS pixels per world unit at 100%, and apply the whole 25–300% zoom range relative to that baseline. Start at 100%, rather than starting zoomed out. On narrow screens focus the central thought when the whole graph cannot fit. Root typography follows root identity, never radius. Wrap labels to measured lobe bounds and use a presentation-only ellipsis when needed; preserve complete text in the editor and sources.
- Opening or resizing details keeps the selected thought visible beside the desktop drawer or above the narrow-screen bottom sheet. Background updates preserve the camera after the first thought arrives. Body dragging never causes the camera to chase a lobe. Closing a thought editor restores focus to its initiating control.

## Browser-local example workspace

- The portfolio example reuses the canonical workspace UI, canvas, validation, and operation reducer. The live workspace remains server-owned; the clearly labeled example stores complete sessions in IndexedDB and performs no API or AI requests.
- The persistent example label reads `Example`. Keep capability and storage explanations in the relevant panels, rather than the canvas header.
- Preserve exact provenance, all operation deltas, the undo/redo cursor and branch, synthesis revision, and export/import fidelity. Display snapshots omit internal history and must never be persisted as the canonical record. Report storage failures instead of silently using unsaved memory.
- The seeded conversation and suggestion are illustrative content, not a claimed recording or live AI output. Each new example is a separate copy; retain existing copies. Live voice, chat, and generation controls are unavailable in the example.
